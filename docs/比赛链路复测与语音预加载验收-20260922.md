## 提示音与语音输入：已实现并上线

### 改动

1. 当前页面按钮、导航、弹窗和下一阶段常用引导提前准备，包含人物介绍、解析完成、样片完成和保存提示。优先准备当前可用操作，后台请求限制为两个并发。
2. 提示音使用独立请求及浏览器缓存，不再排在影片旁白生成后面。同一段声音共享下载，切换焦点只取消播放，不会反复中断并重新下载。
3. 移除 Tab 播报固定的 70 毫秒等待。切换音色按新音色缓存；提示语音的语速设置仍独立于影片。
4. 助手出现时准备识别服务状态和音频处理模块；聚焦输入框或语音按钮时提前建立识别连接。闲置连接最多保留 20 秒，离开页面释放资源。
5. **预加载不请求麦克风、不采集声音。** 用户启动后才申请录音，录音与尚未完成的网络连接并行；连接准备好前的开头音频进入队列，避免必须等连接完成才开始收音。
6. 补齐立即停止、退出页面、取消焦点和网络失败的资源释放。失败录音重试与原有文字保留逻辑继续生效。

### 测量

Windows / Chrome，正式 HTTPS，固定 WAV 作为浏览器测试麦克风，麦克风权限预先授予。测量的是页面触发到播放器开始或录音状态可用的时间，不是声卡输出、人耳听到或真人说话的绝对延迟。使用同一脚本、相同素材；下表为本轮单次或少量复测，不是平均值或性能承诺。

| 指标 | 修改前 | 修改后线上 |
| --- | ---: | ---: |
| 首次 Tab 操作至提示开始 | 529 ms | 99—156 ms |
| 首次语音操作至“正在听” | 2716 ms | 64—91 ms |

直接按 O 的测试中，录音约 64 ms 启动，识别连接约 1807 ms 完成；等待连接期间保留了开头音频，首个识别结果包含“你好”。冷连接仍会影响文字出现时间，因此不能承诺首次操作绝无等待。第一次使用的浏览器麦克风授权也不能由预加载跳过。

## 测试问题与比赛影响

### P1：新上传素材的模型分析失败

复现：创建新视频，选择本次命名为 `QA-比赛链路复核-20260922-52秒静音测试片.mp4` 的既有测试素材。

实际：上传成功，分析开始后约 7.3 秒返回“模型服务返回 500，请检查模型名称与接口兼容性”。页面提供“重试当前阶段”；尝试重试并再次打开任务观察后，任务仍处于分析错误状态。未把旧状态的瞬时轮询当作一次新的失败样本，也不据此推算失败率。

影响：若比赛必须从现场上传一路等到成片，本次验收不通过。该错误是接口返回的事实；尚未确定是模型服务临时异常、请求兼容问题还是其他原因，不能仅凭提示归因于模型名称配置。

建议：优先核对本次任务的模型请求与服务端错误，再用带真实对白的目标比赛片验证完整流程。当前主线使用已准备的演示影片，并明确哪些人物/场景信息来自预设资料。

证据：[上传失败与再次观察](../work/audio-preload-20260922/upload-observe.json)、[页面错误](../work/audio-preload-20260922/upload-observe-final.png)。测试项目 `85d41865-6bc4-4d81-9f71-6d8972104fc9` 保留用于复现。

### P1：默认示例“旁白慢一点”存在不稳定结果

复现：演示视频 → 首个场景 → 输入“旁白慢一点” → 确认执行。

实际：试跑中曾成功；也出现“场景‘城市骑行’新配音超出原声空隙，原版已保留；请精简描述或恢复语速”。最终完整回归再次触发此错误，取消后原版正常播放，再输入“旁白大声一点”，约 1.66 秒返回真实新音轨，随后完成采用、扩展、保存和重开。

判断：拒绝覆盖原声是正确的保护，但默认输入示例与第一场景的可完成性不匹配，会使演示者在展示核心能力时遇到失败。

建议：比赛先采用已验证的音量修改；若要展示放慢语速，提前选择空隙足够的场景或减少旁白文字。后续产品可在确认前提示时长风险，并提供明确的精简方案。

证据：[本轮完整链路记录](../work/audio-preload-20260922/audit-flow.json)、[修改结果](../work/audio-preload-20260922/audit-volume-result.png)。

### P2：从介绍页进入价值演示，仍有多次确认和过程展示

当前顺序为进入体验 → 创建新视频 → 使用演示视频 → 解析完成后进入下一步 → 人物介绍后继续 → 样片就绪后进入下一步 → 播放。步骤说明清楚，但若逐屏讲解，会推迟评委第一次听到实际效果。

1366×768 的首场景页面中，播放与“满意，生成前 3 个场景”已能出现在首屏，语音输入工具栏接近底部；本次未把旧版本的“主要按钮在折叠线以下”继续当作确定缺陷。正式投屏仍需按现场分辨率和缩放彩排。

建议：先从片库直接播放，演示同一片段的旁白开关；评委理解价值后，再用制作流程解释人物与场景及真实修改。进度页称“审校样片”，工作台称“首个场景”，讲解时统一称呼。

## 当前推荐比赛路线

建议编排为约 3—4 分钟；这是路线建议，未完成真人整场计时：

1. **约 20 秒**：说明“给视障用户补充画面信息”，进入片库播放同一片段，切换原声与旁白。
2. **约 30 秒**：展示人物和按完整场景试听，说明预设资料与在线真实修改的边界。
3. **约 45 秒**：用语音或文字输入“旁白大声一点”，展示修改范围和参数，确认执行。
4. **约 30 秒**：试听新旧结果，采用新版；展示一个后续场景，说明未修改内容保留。
5. **约 30 秒**：完成整片、保存到我的视频、刷新重开，以可使用的作品收尾。

留出网络和现场讲解余量。首次比赛电脑使用前完成麦克风授权并打开工作台，给后台资源准备时间。可留一份明确标注的已生成结果备用；不要把备用结果说成现场生成。
