# 旁白助手：普通模式与高级编辑

从「创建新视频 → 使用演示视频 → 认识角色 → 继续到首个场景」进入制作页，右侧会直接展开旁白助手。完整观看页也显示同一助手；窄屏时排列在视频下方。

侧栏采用简化布局：顶部保留场景与模式选择，例句放在正文，底部合并为输入工具栏；快捷键、麦克风说明和播报规则统一放在右上角「使用帮助」。确认卡优先显示具体改动，执行说明可展开；指定场景列表放在阅读区，确认操作始终保留在底部。切换视图、场景或范围时重置阅读位置，避免标题被旧滚动位置裁切。

## 使用方式

- 普通模式：输入要求或点击例句填入输入框，再点「生成修改指令」。指令卡列出场景、字段前后值、执行内容与范围；「查看完整提示词」只读展开实际执行快照使用的文本。
- 高级编辑：六个类别共 29 个字段。自然语言写入的值会直接选中，也可手动修改；返回普通模式时使用同一草稿。「撤销本组修改」恢复本轮基准。
- 确认执行：冻结指令，侧栏保持展开，与播放器同时显示处理状态；完成后侧栏直接显示结果，可比较参数、继续修改或放弃未接受的方案。
- 满意并继续：接受对应场景的方案，并调用既有场景递进流程。指定多个场景时逐个确认。默认只处理当前场景；「当前场景及后续」在本场景满意后才形成后续继承规则。
- 草稿按任务、场景划分版本和场景保存于当前浏览器。刷新保留未执行草稿；中断执行会标记失败，不自动重放。

## 真实能力与模拟边界

原视频、原有配音和既有豆包 TTS 能力继续使用。新增助手的语言理解由规则服务模拟，执行结果为文案与参数预览；当前不调用视频理解或文案改写模型，不把原有音轨冒充新音频。

语音转文字已接入浏览器原生的真实中文麦克风识别，不再插入模拟例句。非输入区域按 O 开始，听到短提示音后说话；再按 O 结束识别，Enter 结束识别并在最终结果返回后发送，Esc 停止并保留文字。文字输入框中 O 仍是普通字母，Enter 发送，Shift+Enter 换行；中文输入法组合输入不会触发发送。发送只整理待确认指令，不直接执行。

麦克风首次需要浏览器授权；识别由浏览器服务提供，可能需要网络。权限拒绝、服务不支持、网络错误、无语音、结束超时或仅有中间结果时不会自动发送。开始录音会暂停视频、旁白和站内语音；离开页面会取消识别，旧回调不应用到其他场景。本 Demo 保存草稿文字，不保存录音文件。

播报规则可在助手右上角「使用帮助」查看：自动读位置、简短修改摘要、澄清和关键执行状态；Tab 读控件名称及必要状态；长提示词、历史、整套标签、逐字输入和重复进度不自动读。完整摘要与输入文字可以主动听取。读屏优先时关闭站内语音并保留 ARIA 状态。麦克风开启后的短提示音没有文字，避免被当成修改要求。

提示词包含实际场景、现有旁白、时间窗口、完整生效标签、人物覆盖、执行计划和返回约束。缺失的分镜、人物出入与文字转写明确列为待核对。文案待改写时展示现有原文，不生成未核实的画面事实；音频未生成、时长未测量、同步未验证。

音色三档是指令标签；初始值适配现有旁白设置。这些标签不会改动全站引导音色、Tab 语速或角色介绍语速。旁白参数不会改变原视频 playbackRate 或原声音轨。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `public/assistant/schema.js` | 六类 29 字段、类型、默认值、选项与显示名称 |
| `public/assistant/context.js` | 现有影片场景、稳定人物 ID、旁白窗口及缺失事实说明 |
| `public/assistant/model.js` | 草稿合并、差异、自然语言规则、确定性提示词、执行快照、接受与撤销 |
| `public/assistant/services.js` | 可替换的 `parse` / `run` 服务；目前为 Mock；测试可注入失败 |
| `public/assistant/view.js` | 侧栏、模式切换、分类、字段控件、确认卡、提示词与结果视图 |
| `public/assistant/voice-input.js` | 真实浏览器识别适配、最终文字提交、权限与网络错误、停止和过期回调处理 |
| `public/assistant/speech-policy.js` | 播报白名单、口语化摘要、O / Enter / Shift+Enter / Esc 规则 |
| `public/experience.js` | 现有任务、播放器、处理状态、草稿保存和下一阶段的接入 |
| `public/focus-reader.js` | 单选项的名称和选中状态播报 |
| `public/styles.css` | 黑白侧栏、滚动区、固定操作区与窄屏布局 |
| `tests/assistant.test.mjs` | 标签合并、否定、集合、别名、范围、过期结果和两次确认等行为测试 |

替换真实服务时保留 `assistantServices.parse(text, context, draft)` 与 `assistantServices.run(snapshot)` 的边界。只有真实音频与场景、设置及版本一致、通过时长校验，才将结果标记为可试听。不要把完整提示词传给语音合成当旁白朗读。

## 本轮验证记录

- 自动测试：29 字段与默认值；普通与高级合并；按组撤销；集合增删；否定和不支持的语速；人物 ID 绑定与歧义阻断；六字段组合例子；临时解释不改偏好；独立场景事实与基准；仅音量计划；重复执行、过期返回、失败、中断、候选叠加、放弃、继承及逐场景接受。
- 浏览器实际操作：例句只填入；语速生成待确认卡；切换高级模式保留 0.85 倍；手动 +3 dB 合并同卡；查看实际完整提示词无占位符；关闭预览恢复焦点；确认执行与结果就绪时侧栏保持展开；回车只发送待确认要求；输入框保留普通字母 O；结果保持首场景，满意后进入前三场景；刷新恢复草稿；方向键切换模式；第二场景继承已接受参数；指定第二、第三场景分别编译；必须逐项确认多场景结果。
- 布局：实看普通卡、高级声音编辑、完整提示词、模拟结果四种状态。390 CSS 像素宽下侧栏无横向溢出，底部确认按钮位于视口内。
- 语音识别适配测试：中文配置、停止输出音频、识别中间结果更新、最终结果发送一次、错误不发送、取消后过期回调不应用、停止超时处理。与原项目测试一起共 60 项通过。
- 边界：没有启用用户麦克风做实录测试；浏览器实际权限、识别服务与转写质量需用户授权后体验。未接入真实模型改写，未验证新增标签对应的真实新音频；没有声称通过无障碍认证。系统级读屏与不同手机浏览器仍需真实用户进一步体验。

语音输入接口依据：[Web Speech API 规范](https://webaudio.github.io/web-speech-api/)与 [Chrome 官方文档](https://developer.chrome.com/blog/voice-driven-web-apps-introduction-to-the-web-speech-api)。
