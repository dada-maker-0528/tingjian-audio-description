# 本地运行与接口

## 启动

要求 Node.js 22.22 或更新的兼容版本、npm、可调用的 FFmpeg。执行 `npm ci`，根据根目录 `.env.example` 创建 `.env`，再执行 `npm run dev`。默认地址为 http://127.0.0.1:5294 。程序只监听本机。

必需的真实处理配置：

- `AIMEDIA_API_KEY`：视频理解和原声/反馈转写服务凭据。
- `AIMEDIA_PROVIDER`、`AIMEDIA_BASE_URL`、`AIMEDIA_VISION_MODEL`、`AIMEDIA_ASR_MODEL`：沿用原项目的模型协议，示例为 MiniMax。真实兼容性需使用有效服务验证。
- `VOLC_TTS_KEY`：用户明确提供并授权本机使用的豆包语音凭据，仅写入被 Git 忽略的 `.env`，不进入前端、文档或测试日志。
- `VOLC_TTS_RESOURCE_ID`：默认 `seed-tts-2.0`。
- `TINGJIAN_TTS_PROVIDER`：本地默认 `doubao`。

可选 `PORT`、`FFMPEG_PATH`、`AIMEDIA_DATA_DIR`。默认本机数据在 `.aimedia/`，已排除 Git。语音反馈录音保留在所属任务目录用于重试，不通过静态媒体接口公开。自行删除数据前应备份需要保留的作品。

没有配置密钥时，演示入口仍可使用；真实上传会保留素材并报告缺少的服务，不会替换成演示结果。采样画面和音频将发送到所配置的服务，真实处理可能产生费用。

`npm run dev:worker` 保留原 Worker 演示运行方式，使用 `.dev.vars`。`npm run build` 仍构建 Worker 演示包，不会将本地 Node 视频处理服务部署到云端。

## 数据与操作

真实任务阶段为 `analyzing → roles → short → medium → verify（仅返工时）→ full`。每个阶段分别记录 `generating/review/paused/error/interrupted/complete` 等状态。

样片从有旁白空间的候选画面区间选择，目标7秒；中样片从同一起点覆盖至多45秒；复验选择不同于原短片的候选区间。原片太短时显示真实时长，没有适合复验的另一段则明确阻塞，不复用旧样片冒充通过。

整片从0秒到原片末尾按不超过60秒分块处理，完成块持久保存，最终拼接独立旁白轨并检查时长与解码。播放始终使用原视频及独立旁白轨，原声音量不经过自动压低。候选设置只有样片确认后才成为已确认设置；返回首页不会丢弃任务。

## HTTP 接口

业务响应为 `{ok:true,data:...}` 或 `{ok:false,error:...}`。所有修改请求需要 `X-Tingjian-Request: 1`，拒绝跨站请求与非本机 Host；不开放远程访问或跨设备共享。

| 接口 | 输入/结果 |
|---|---|
| `GET /api/capabilities` | 本地能力与配置是否存在，不返回密钥，不代表服务已实测可用 |
| `GET /api/bootstrap` | 本机真实作品及制作草稿 |
| `POST /api/upload` | 视频原始字节；`X-Filename` URL编码文件名，`X-Request-Id`幂等标识，`X-Voice`支持的音色ID；返回任务并自动分析 |
| `GET /api/projects/:id` | 最新任务、版本、角色、媒体地址和状态 |
| `POST /api/projects/:id/listen-action` | `{action,revision,requestId,...}`，动作见下文 |
| `POST /api/projects/:id/listen-voice` | 最多8MB录音，返回转写文字及录音ID；失败保留录音 |
| `POST /api/projects/:id/listen-voice?recordingId=...` | 重试当前版本的已保留录音，无需再次录制 |
| `GET /media/:id/:file` | 原片/旁白等允许的媒体文件，支持 Range 定位；拒绝录音和项目配置文件 |
| `/api/tts/status`、`POST /api/tts` | 保留原演示语音接口，使用既有响应格式 |

`listen-action` 支持 `accept`、`feedback`、`voice`、`pause`、`retry`、`save`、`position`。确认带 `versionId`；反馈带 `text`；换音色带 `voice`；播放位置带 `position`（秒）。任务版本过期返回409，重新获取后由用户操作。相同请求标识不会重复执行。

反馈理解明确为规则匹配，支持语速、旁白音量、信息密度及当前片段重做；不是任意自然语言对话。单句改写、角色改名、否定或不明确意见不自动执行。语音转写得到文字后由用户提交，不直接把识别结果当确认。

## 验证命令

- `npm run check`：脚本语法。
- `npm test`：协议、接口、状态、脚本审查、真实FFmpeg媒体处理；模型响应被隔离模拟，不消耗外部额度。
- `npm run test:browser`：独立临时数据目录与本机受控模型端点，Chrome自动键盘流程。默认使用已安装Chrome，也可设置 `PLAYWRIGHT_EXECUTABLE_PATH`。不使用用户模型凭据。
- `npm run build`：原 Worker 演示包构建。

浏览器截图和JSON结果保存在 `.test-artifacts/browser/`，不加入 Git。NVDA、人工蒙眼走查、视障用户试用与真实模型测试需另行执行并记入验证记录。

## 统一豆包提示音（2026-09-21）

用户最新确认：全站不能再播放浏览器机械提示音。已删除按钮朗读和引导兜底的系统语音调用，移除演示播放器对旧 fallbackAudio 的播放入口。已确认的豆包预制旁白或匹配版本缓存仍可复用；没有匹配声音时明确失败并允许重试。

- `GET /api/tts/ui-status?voice=vivi`：已完成条数、总条数和批处理状态，使用标准业务封装。
- `POST /api/tts/prepare-ui`：JSON `{ "voice": "vivi" }`，带 `X-Tingjian-Request: 1`。后台串行准备固定清单，重复请求复用同一批任务。
- `GET /api/tts/ui-audio?voice=vivi&text=…`：只读取已生成音频，不触发付费合成。
- `POST /api/tts` 的 guide 请求：先读取本机缓存，缺少才调用豆包；相同并发请求合并，成功后原子保存完整 WAV。
- 缓存依据文本、音色、资源标识、采样率和格式版本生成，不含凭据。刷新、服务重启可以复用，换音色不能串用。
- 用户切换焦点立即停止等待和播放，过期响应不得开口。已开始的服务端短句可完成并缓存，避免下次再次计费。
- 固定清单维护在 `public/ui-speech.js`；动态文件名、人物名或进度按首次请求生成并缓存，不承诺无限动态内容都已预录。
- 密钥配置及生成音频保存在本机，不随本次源码改动进入 Git。Worker 部署仍支持豆包与浏览器缓存，本机批量预生成接口属于 Node 服务。
